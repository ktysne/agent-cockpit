# agent-cockpit の使い方

導入の手順は [setup.md](setup.md) にあります。この文書は、導入した後の画面と機能を説明します。

## 起動と終了

常駐サーバーは、セッションの開始時にフックが起動します。手で起動するときは、リポジトリのルートで次を実行します。

```powershell
npm start
```

常駐サーバーは `127.0.0.1:47821` で待ち受け、ブラウザーで `http://127.0.0.1:47821/` を開くと画面が表示されます。
保存先は `~/.agent-cockpit/` です。`AGENT_COCKPIT_HOME` で保存先を、`AGENT_COCKPIT_PORT` または `--port` でポートを変えられます。
手で起動した常駐サーバーは、起動した端末で `Ctrl+C` を押すと終了します。

## タスクトレイ(Windows)

リポジトリ直下の `start-tray.cmd` をダブルクリックすると、タスクトレイを起動してダッシュボードを開きます。起動の瞬間に黒いウィンドウが一瞬表示されます。
[setup.md](setup.md) の手順で作ったショートカットから起動すると、黒いウィンドウは表示されません。
どの起動方法も、PowerShell の実行ポリシーが `RemoteSigned` 以上であることを前提にしています。

- 初回起動時に、許可待ちと判断待ちが増えたときに Windows の通知を出すか確認します(既定はオフ)。右クリックメニューの「待ち件数を通知する」で切り替えられ、設定は `AGENT_COCKPIT_HOME` の `tray.json` に保存されます。常駐サーバーなどのエラー通知は、この設定にかかわらず表示します。
- ダッシュボードのウィンドウは専用のプロファイルの Edge で開きます。PR や CI などのリンクは OS の既定のブラウザーで開きます。
- ダッシュボードを閉じても、タスクトレイは動き続けます。メニューの「終了」を選ぶと、ダッシュボードとタスクトレイを終了します。常駐サーバーは動き続けます。

ショートカットを作り直すと、起動引数も更新されます。ログオン時の自動起動をやめるときは、`-Remove -Startup` を付けて実行します。

```powershell
powershell.exe -NoProfile -File ".\src\tray\install-shortcut.ps1" -Startup
powershell.exe -NoProfile -File ".\src\tray\install-shortcut.ps1" -Remove -Startup
```

### 常駐サーバーの再起動

タスクトレイのメニューに「常駐サーバーを再起動」があります。確認すると、`server.json` の PID のプロセスコマンドラインに、このチェックアウトの `src/server/server.js` が含まれる場合だけ停止して起動し直します。ファイルが無い場合や別のプロセスを指している場合は、停止せずに起動処理へ進みます。ダッシュボードのウィンドウは閉じず、開いている画面は自動でつなぎ直します。

再起動で残るものと消えるものは次のとおりです。

- ファイルから復元するもの:MCP で登録したタスクと判断事項、`AskUserQuestion` から作る判断事項、それらへの回答の記録、表示設定、一覧から外したセッション、離席中
- 消えて、次のイベントから組み立て直すもの:イベントから組み立てるセッション状態とサブエージェント、画面で終了にしたサブエージェント
- 送信済みで未配信の回答は残ります。ただし再起動で質問の待ちが切れるため、次の `UserPromptSubmit` または `PostToolBatch` まで配信されません。
- テーマはブラウザーごとの `localStorage` に残ります。

## 表示

- 「設定」の画面の「表示」から配色を変更できます。
- 表示モードを「プロダクト別」と「種類別」で切り替えられます。上部の件数タグを押すとその種類を隠し、「すべて表示する」で戻せます。
- プロダクト別では、各プロダクトを固定、上下移動、折りたたみできます。
- 表示設定はブラウザーの `localStorage` に保存されます。保存できない場合も操作できますが、再読み込みすると初期状態に戻ります。
- プロダクトごとに、離席中の期間に起きた変化のうち、最後に既読にした後のタスク完了、PR 作成、仮適用した判断、CI 失敗、PR マージを「前回見てから」に表示します。新しい判断事項には「新着」を付けます。
- 許可待ちは表示だけで、画面から許可を出す機能はありません。
- フックが送るツール入力は要約だけです。

## タスクと判断事項

メインセッションは計画を立てた後に MCP ツール `cockpit_set_tasks` を呼び、タスクと完了条件を登録します。タスクの状態や完了条件が変わったときは、一覧全体を置き換えます。
`away.js` は開始時と各ターンの入力時にタスク登録の決まりを知らせ、`PostToolBatch` の `answer.js` は条件に応じて作業中の登録を促します。

`AskUserQuestion` の質問は、フックが自動で判断事項にします。
推奨は、単一選択の質問で label に「(推奨)」または「(Recommended)」(括弧は全角・半角を許容し、英語の大文字小文字は区別しない)を含む選択肢、または MCP の `cockpit_add_decision` で `recommended: true` を明示した選択肢がちょうど 1 つのときに付けます。description は判定に使いません。
複数の選択肢に含まれる場合や、質問が複数選択の場合は推奨なしとして扱います。
質問せずに推奨を適用する判断は、`cockpit_add_decision` または `cockpit_update_decision` で記録します。

画面は判断事項の状態、待ち時間、背景、質問、選択肢を表示します。
解決済みと取り下げの判断事項と完了したタスクは折りたたまれます。作業中のタスクがあるセッションでは、未着手のタスクも折りたたまれます。
メインセッションでの MCP ツールの使い方は [agent-cockpit スキル](../skills/agent-cockpit/SKILL.md) にあります。

## 回答と離席中

ダッシュボードでは「推奨案で OK」、選択肢の選択、指示を組み合わせて回答できます。単一選択は 1 つ、複数選択は複数の選択肢を押して選び、「回答を送る」で送信します。「推奨案で OK」と選択肢の選択は排他的です。

回答は次の経路でセッションへ届きます。

- 回答待ちの質問への回答は、`PreToolUse` の `updatedInput` で渡します。元の `tool_input` を保ったまま `answers` を加えます。
- 作業中は `PostToolBatch` から回答を差し込みます。
- 停止中は、`Stop` の `asyncRewake` フックが回答を待ってセッションを起こします。
- `UserPromptSubmit` の `answer.js` は、渡した回答が反映されていない場合に、最大 3 回まで文脈へ差し込み直します。
- `awaitingAnswerUntil` がある質問の回答は、`PostToolBatch`、`UserPromptSubmit`、`Stop` からは渡しません。
- 回答本文は常駐サーバーのメモリーとフックの出力にだけ置きます。

離席中は、画面上部のチェックボックスか、タスクトレイの右クリックメニューで切り替えます。
有効な間、`AskUserQuestion` は設定画面の「離席中に質問の回答を待つ時間」に従ってダッシュボードの回答を待ちます(1〜30 分、既定 5 分)。締切までに回答が無ければ質問を止め、推奨で作業を続けるようフックが伝えます。

- finish が常駐サーバーに届いた場合、回答があればその内容を返します。それ以外は離席状態を確認し、離席中が続いていれば質問を `deny` して推奨で進め、判断事項を `provisional` にします。離席中が解除されていれば `released` としてデスクトップアプリのダイアログへ戻します。
- finish も常駐サーバーに届かなかった場合、フックは離席状態を確認できないため、常に質問を `deny` して推奨で進めます。
- 回答待ちのフックから 30 秒間 long-poll が届かない場合は待ちを解除し、届いていた回答も破棄してデスクトップアプリのダイアログへ戻します。
- 許可のダイアログには答えず、破壊的な操作、PR のマージ、`main` への push は判断待ちに残します。
- `claude -p` では `AskUserQuestion` が無効なため、この制御は対話セッションでだけ働きます。

## PR の表示とマージ(GitHub CLI と連携したとき)

セッションが `gh pr create` で作った PR は自動で登録されます。MCP ツール `cockpit_add_pr` に PR の URL を渡すと、そのセッションへ登録して読み取り専用のスタック表示に追加できます。

表示設定の「『マージできます』と出す条件」では、「マージの操作ができる」「CI も通っている(CI が無ければ問わない)」「クロスレビューも済んでいる(不要としたものを含む)」から選べます。既定はクロスレビューまで済んでいることです。条件を満たした PR は緑の「マージできます」、操作はできるが条件が残る PR は灰色の「マージ操作は可能」と未達条件を表示します。未達でも手動マージはでき、確認欄の先頭に未達条件を示します。

記録済みのスタック最下段 PR は、画面で方式とリモートブランチ削除の有無を確認してマージできます。即時マージは、画面に表示した head の SHA を `--match-head-commit` で照合します。

- マージ結果は作成元セッションへ配信し、直上の PR があるスカッシュまたはリベースでは積み直しを依頼します。
- マージ済みの一覧は 24 時間表示します。

### レビュー収束後マージ(ai-cross-review と連携したとき)

確認欄の「レビュー収束後マージ」は既定でオフです。オンにすると、常駐サーバーが予約を保存し、PR の状態を取り直すたびにクロスレビューの最後の収束記録、CI、GitHub のレビュー承認、スタック位置、ドラフトとコンフリクトを確かめます。条件がそろうと通常のマージ手順で、収束記録の SHA を `--match-head-commit` に渡してマージします。収束後に push されたら、新しい head の収束まで待ちます。表示設定から予約チェックを既定でオンにできます。

- 確認欄の「予約を取り消す」は、ローカルの予約を消します。PR がマージ以外で閉じられたときや、クロスレビューの最後の記録が `halted` になったときも予約を取り消して、画面と作成元セッションへ知らせます。
- 旧 GitHub 自動マージ形式の保存データは読み込み時に捨て、GitHub 側は操作しません。

PR の差分が軽微でクロスレビューを省くときは、メインセッションから MCP ツール `cockpit_skip_review` に owner、repo、PR 番号、現在の head SHA、理由を渡します。記録はその head に限り、push で head が変わると無効になります。カードの「レビュー不要にする」からも記録でき、取り消せます。

## 経路の設定(claude-codex-bridge、ai-cross-review と連携したとき)

claude-codex-bridge を入れているときは、ダッシュボード上部の「経路の設定」で、サブエージェントの経路を「既定」「Codex」「Claude」から選びます。
ai-cross-review を入れたリポジトリでセッションを開いているときは、クロスレビューのレビュアーも同じ欄で選べます。ai-cross-review はレビューを回す直前に `node tools/cross-review.js route` でこの設定を読みます。

- 常駐サーバーは、サブエージェントとクロスレビューの両方を `AGENT_COCKPIT_HOME` の `routing.json` に保存します。設定ファイルが読めない場合は、両方を「既定」として扱います。
- サブエージェントの経路は起動時に記録され、そのサブエージェントが終了するまで変わりません。起動時の記録は `AGENT_COCKPIT_HOME` の `route-agents/` に置きます。同じサブエージェントが再開しても初回の経路を使い、24 時間使われていない記録は、新しいサブエージェントの開始時に削除します。
- 2 つの連携がどちらも無いときは、「経路の設定」の欄を出しません。
