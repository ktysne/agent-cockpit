Agent Cockpit のシステム構成

Claude Code と Codex（CLI、デスクトップ）のセッション状態を、127.0.0.1 の常駐サーバーが集めてダッシュボードに表示する。ダッシュボードで書いた回答は、フック経由でセッションへ戻る。詳細版

データの流れ

  1. イベント（フック → サーバー）：event.js がツール実行、通知、サブエージェントの開始と終了などを POST /api/events で送る。サーバーはここからセッションの状態を組み立てる。常駐サーバーが動いていなければ、SessionStart の event.js が起動する。Codex のセッションは、同じスクリプトを最後の引数 codex 付きで登録して送る。
  2. 回答・知らせ（サーバー → フック → セッション）：answer.js がサーバーに問い合わせ、ダッシュボードで書かれた回答、PR のマージ結果の知らせ、衝突の解消の依頼、タスクの登録の催促をセッションの文脈として渡す。離席中は、away.js が質問ツール（Claude は AskUserQuestion、Codex は request_user_input）を止めてダッシュボードの回答を待ち、その回答を質問の答えとして返す。待機中の Claude のセッションは Stop のフック（asyncRewake）で起こす。Codex には同じ仕組みが無いので、PostToolUse と Stop のフックで渡し、離席中は Stop で回答を待つ。
  3. 計画・PR（MCP → サーバー）：メインセッションが MCP ツールを呼ぶと、MCP サーバーが計画（タスク、完了条件、判断事項）、PR、クロスレビュー不要の記録を常駐サーバーへ送る。
  4. 状態の表示（サーバー → ダッシュボード）：ダッシュボードは GET /api/state を 2 秒ごとに取得して画面を描き直す。
  5. 回答・操作（ダッシュボード → サーバー）：回答、離席中の切り替え、経路と表示の設定、PR のマージ確認と予約、衝突の解消の依頼、診断ログの削除などを送る。回答と依頼はサーバーの配信待ちに置かれ、②で届く。マニュアルと外部のページ（PR など）は、サーバーに頼んで既定のブラウザーで開く。
  6. GitHub（サーバー ⇄ GitHub）：gh CLI で PR と CI の状態を 60 秒ごとに取得する。マージできるのは、開発者が画面で確認したスタック最下段の PR だけで、画面で見た head の SHA を照合する。レビュー収束後マージの予約は、クロスレビューの収束を記録した head の SHA で照合する。新しいバージョンのタグは git ls-remote で 6 時間ごとに確かめ、画面で知らせる。
  7. 読み取り（ファイル → サーバー）：~/.claude と ~/.codex を 10 秒ごとに読み、稼働中のセッション、利用者の中断、Codex のスレッド名と会話の終了を拾う。どちらも公開仕様ではないので、読めなくても本体は動く。

構成要素

フック

Claude Code と Codex の設定に登録するスクリプト群。イベントを送り、回答と知らせをセッションへ渡す。route.js は Claude だけに登録し、経路の設定をサブエージェントへ伝え、Claude を選んだ担当が Codex を起動しようとしたら止める。

MCP サーバー

セッションが計画、判断事項、PR を書き込むための窓口。常駐サーバーへ HTTP で転送する。Codex からの呼び出しはクライアント名で見分け、記録先のセッションを要求に付いた ID で決める。

常駐サーバー

すべての情報が集まる中心。127.0.0.1 にだけ待ち受け、外部パッケージを使わず Node.js で動く。30 分要求が無く、セッションも無いと終了し、次のフックが起動し直す。Claude Code の無い環境でも同じ条件で終了する。

ダッシュボード

常駐サーバーが配信する画面。状態の表示と、回答やマージ確認の入力を担う。ウィンドウのタイトルにバージョンを出し、新しいバージョンがあれば更新の依頼文を渡す。

タスクトレイ

Windows 用の常駐アイコン。サーバーの起動と再起動、ダッシュボードを開く操作、離席中の切り替え、待ち件数の通知を担う。

診断ログ

常駐サーバー、フック、MCP、画面の出来事を ~/.agent-cockpit/diagnostics/ に記録する。会話、質問と回答、ツールの入出力、秘密値は残さない。設定画面の入口から読み、書き出し、削除できる。

マニュアル

manual/ で組み立てた利用者向けの説明。紹介ページと一緒に https://ktysne.info/agent-cockpit/manual/ へ配信し、設定画面の入口から既定のブラウザーで開く。

フック、MCP サーバー、トレイの起動処理は、共通の接続処理（src/client）で常駐サーバーを探し、動いていなければ起動する。許可待ち（パーミッションのダイアログ）は表示するだけで、ダッシュボードから許可を出す経路は無い。連携（任意）の道具が無くても本体は動く。
