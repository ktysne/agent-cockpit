Agent Cockpit のシステム構成

Claude Code のセッション状態を、127.0.0.1 の常駐サーバーが集めてダッシュボードに表示する。ダッシュボードで書いた回答は、フック経由でセッションへ戻る。詳細版

データの流れ

  1. イベント（フック → サーバー）：event.js がツール実行、通知、サブエージェントの開始と終了などを POST /api/events で送る。サーバーはここからセッションの状態を組み立てる。常駐サーバーが動いていなければ、SessionStart の event.js が起動する。
  2. 回答・知らせ（サーバー → フック → セッション）：answer.js がサーバーに問い合わせ、ダッシュボードで書かれた回答、PR のマージ結果の知らせ、衝突の解消の依頼、タスクの登録の催促をセッションの文脈として渡す。待機中のセッションは Stop のフックで起こす。離席中は、away.js が AskUserQuestion を止めてダッシュボードの回答を待ち、その回答を質問の答えとして返す。
  3. タスク・判断・PR（MCP → サーバー）：メインセッションが MCP ツールを呼ぶと、MCP サーバーが計画（タスク、完了条件、判断事項）、PR、クロスレビュー不要の記録を常駐サーバーへ送る。
  4. 状態の表示（サーバー → ダッシュボード）：ダッシュボードは GET /api/state を 2 秒ごとに取得して画面を描き直す。
  5. 回答・操作（ダッシュボード → サーバー）：回答、離席中の切り替え、経路と表示の設定、PR のマージ確認と予約、衝突の解消の依頼などを送る。回答と依頼はサーバーの配信待ちに置かれ、②で届く。マニュアルと外部のページ（PR など）は、サーバーに頼んで既定のブラウザーで開く。
  6. GitHub（サーバー ⇄ GitHub）：gh CLI で PR と CI の状態を 60 秒ごとに取得する。マージできるのは、開発者が画面で確認したスタック最下段の PR だけで、画面で見た head の SHA を照合する。レビュー収束後マージの予約は、クロスレビューの収束を記録した head の SHA で照合する。

構成要素

フック

Claude Code の設定に登録するスクリプト群。イベントを送り、回答と知らせをセッションへ渡す。route.js は経路の設定をサブエージェントへ伝え、Claude を選んだ担当が Codex を起動しようとしたら止める。

MCP サーバー

セッションが計画、判断事項、PR を書き込むための窓口。常駐サーバーへ HTTP で転送する。

常駐サーバー

すべての情報が集まる中心。127.0.0.1 にだけ待ち受け、外部パッケージを使わず Node.js で動く。30 分要求が無いと終了し、次のフックが起動し直す。

ダッシュボード

常駐サーバーが配信する画面。状態の表示と、回答やマージ確認の入力を担う。

タスクトレイ

Windows 用の常駐アイコン。サーバーの起動と再起動、ダッシュボードを開く操作、離席中の切り替え、待ち件数の通知を担う。

マニュアル

manual/ で組み立てた利用者向けの説明。常駐サーバーが /manual/ で配り、設定画面の入口から既定のブラウザーで開く。

フック、MCP サーバー、トレイの起動処理は、共通の接続処理（src/client）で常駐サーバーを探し、動いていなければ起動する。許可待ち（パーミッションのダイアログ）は表示するだけで、ダッシュボードから許可を出す経路は無い。連携（任意）の道具が無くても本体は動く。
