Agent Cockpit のシステム構成

Claude Code のセッション状態を、127.0.0.1 の常駐サーバーが集めてダッシュボードに表示する。ダッシュボードで書いた回答は、フック経由でセッションへ戻る。詳細版

データの流れ

  1. イベント（フック → サーバー）：event.js がツール実行、通知、サブエージェントの開始・終了などを POST /api/events で送る。サーバーはここからセッションの状態を組み立てる。
  2. 回答・通知（サーバー → フック → セッション）：answer.js と away.js がサーバーに問い合わせ、ダッシュボードで書かれた回答や PR マージ結果の通知を受け取って、セッションの文脈（または AskUserQuestion の回答）として渡す。
  3. タスク・判断・PR（MCP → サーバー）：メインセッションが MCP ツールを呼ぶと、MCP サーバーが計画（タスク、完了条件、判断事項）と PR を常駐サーバーへ登録する。
  4. 状態の表示（サーバー → ダッシュボード）：ダッシュボードは GET /api/state を定期的に取得して画面を描き直す。
  5. 回答・操作（ダッシュボード → サーバー）：回答、離席中の切り替え、経路の設定、PR のマージ確認などを送る。回答はサーバーの配信待ちに置かれ、②で届く。
  6. GitHub（サーバー ⇄ GitHub）：gh CLI で PR と CI の状態を取得する。マージは開発者が画面で確認したスタック最下段の PR だけを、見た head の SHA で照合して行う。

構成要素

フック

Claude Code の設定に登録するスクリプト群。イベントを送り、回答を受け取ってセッションへ渡す。

MCP サーバー

セッションが計画・判断事項・PR を書き込むための窓口。常駐サーバーへ HTTP で転送する。

常駐サーバー

すべての情報が集まる中心。127.0.0.1 にだけ待ち受け、外部パッケージを使わず Node.js で動く。

ダッシュボード

常駐サーバーが配信する画面。状態の表示と、回答やマージ確認の入力を担う。

タスクトレイ

Windows 用の常駐アイコン。サーバーの起動・再起動と、ダッシュボードを開く操作を担う。

許可待ち（パーミッションのダイアログ）は表示するだけで、ダッシュボードから許可を出す経路は無い。連携（任意）の道具が無くても本体は動く。
