# Codex への配信

Codex 対応の順序 5(#175)の設計である。
ダッシュボードから Codex のセッションへ届けるもの(判断事項の回答、セッションへの通知、タスク登録の促し)を、Claude と同じ仕様で届ける。
計画と順序の正本は [2026-10-11-codex-rebuild.md](../handover/2026-10-11-codex-rebuild.md) にある。
質問への回答の届け方は [codex-question.md](codex-question.md) にある。

## 方針

Claude と同じ目的の処理と表示は、同じ仕様にする(開発者の決定)。
この資料は、Claude の今の仕様を既定とし、Codex で同じにできない点だけを「差」として決める。

## 範囲

Issue #175 は、cockpit が管理する app-server で自由な指示を送る旧設計で書かれている。
配信はフックで行い、app-server は作らない(計画書の決定済みの判断「配信の経路」)。
今のモックと Claude の実装には、自由に書いた指示を送る機能は無い。
ダッシュボードからセッションへ届けるのは、判断事項の回答(指示の欄を含む)、セッションへの通知(PR のマージなど)、タスク登録の促しである。
この資料はこの 3 つを対象にする。

## Claude の仕様(既定)

- 作業中: ツールの区切り(`PostToolBatch`)の `additionalContext` で届ける。
- 入力のとき: `UserPromptSubmit` の `additionalContext` で届ける。判断事項の回答は、反映の記録(`cockpit_update_decision`)が来るまで最大 3 回届ける。
- ターンの後: 対話セッションでは `Stop` のフックが裏(`asyncRewake`)で最大 3600 秒待ち、届いたらセッションを起こして続けさせる。在席中も離席中も待つ。単発の呼び出し元が指定する待機方法は[「Claude の単発実行」](server.md#claude-の単発実行)に従う。
- 届けた時刻(`deliveredAt`)と反映の時刻(`reflectedAt`)を分けて記録し、届けただけでは反映済みにしない。

## 差と決定

### 作業中と入力のとき

Codex には `PostToolBatch` が無いので、`PostToolUse` の `additionalContext` で、`PostToolBatch` と同じ内容を届ける。
通常の Codex セッションは入力時に Claude と同じ処理を使う。委譲した thread には判断事項や通知を配信せず、[委譲した Codex の表示と書き込み](codex-delegation.md#表示と書き込み)の規則を使う。
どちらも順序 4 で入れた(PR #400)。

### ターンの後

Codex には裏で待つ仕組み(`asyncRewake`)が無い。
同期の `Stop` のフックで待つと、その間 Codex の画面は作業中になり、`Esc` で中断できる。
離席中だけ `Stop` で待ち、届いたら届けた内容を理由に続行(`decision: block`)させる(開発者の決定)。
離席中は Codex の画面を見る人がいないので、作業中の表示が続いても困らないためである。
在席中は待たず、ターンの終わりの時点で未配信のものがあれば一度だけ続行させ、後から届いたものは次の入力かツールの後に届ける。
待つのは、cockpit にセッション行のある Codex のセッションだけにする。
委譲した Codex の thread(セッション行が無い)を待たせると、離席中は委譲した実行がそのたびに上限まで止まるためである。

待つ間に次のどれかが起きたら、何も返さずに待つのをやめる。

- 離席が解除された。
- 同じセッションで入力かツールの実行が始まった。
- セッションが終わった。
- 親のプロセスが終わった。
- 待ち始めてから上限に達した。

待つ上限は、Claude の `Stop` のフックと同じ 3600 秒にする。
フックの上限(`timeout`)も 3600 秒にし、フックの側で少し前にやめる。
フックが上限を超えると Codex はフックの失敗として扱うので、失敗の表示を出さないためである。

## 範囲の外

- Issue #175 の配信台帳(送信中、受付、適用、未確認の区別と、結果が不明な配信の再送の禁止)は、app-server を使う旧設計の要件である。フックによる配信では、Claude と同じ `deliveredAt` と `reflectedAt` の区別にとどめる。
- 常駐サーバーの再起動の後の配信は順序 7 で扱う。
