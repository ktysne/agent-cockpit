# 診断ログ

agent-cockpit の不具合を調べるための記録を、利用者の端末の中にだけ残す。
仕様は session-score-player の診断ログ(`js/logger.js`、`documents/developer/md/logging.md`)を踏襲し、常駐サーバーとフックの構成に合わせて置き換える。

## 目的と方針

- フック、常駐サーバー、MCP、画面が別々のプロセスで動くので、どこで何が起きたかを後から追えるようにする。
- 記録は端末の中にだけ置き、外へ送る機能は作らない。外に出るのは、利用者が画面で「コピー」か「書き出す」を押したときだけである。
- 記録は、記録してよい項目だけを常駐サーバーの受け口で選んで残す。送る側の自制には頼らない。

## 記録しない情報

次の情報は、どのレベルでも記録しない。

- 会話の本文、プロンプト、ツールの入力と出力、質問と回答の本文、計画やタスクの文
- `CLAUDE_CODE_MESSAGING_TOKEN` と、常駐サーバーの起動ごとの秘密値(`secret`、`uiSecret`)
- 要求のヘッダー
- `gh`、`git`、プロセスの照会のエラー文と標準エラー。Node の `execFile` のエラー文はコマンド行と標準エラーを含むので、記録するのは `code`、`signal`、終了コード、失敗の分類だけにする
- `~/.claude/sessions/*.json` と Codex の記録ファイルの中身
- 作業ディレクトリのパスと、ホームディレクトリの下のユーザー名(パスはプロダクト名に置き換え、残ったユーザー名は `<redacted>` に置き換える)

次の情報は記録する。

- 記録の識別子(固定の英数字。例: `hook.rejected`、`gh.failed`)、レベル、時刻
- フックのイベント名、provider、ツール名、セッション ID の先頭 8 文字、プロダクト名
- PR のリポジトリ名と番号
- 件数、長さ、所要時間、成否、失敗の分類、HTTP の状態、照合の結果(一致、不一致、欠落)
- 常駐サーバーの pid、ポート、版、ソースの commit

## レベル

レベルは参考元と同じ 5 段階で、既定は「情報まで」である。

| レベル | 画面の表示 | 残す記録 |
|---|---|---|
| `silent` | 記録しない | なし |
| `error` | エラーのみ | 失敗 |
| `warn` | 警告まで | 失敗と、想定外だが続けられたこと |
| `info` | 情報まで(既定) | 上に加えて、起動、停止、採らなかったイベント、集計 |
| `debug` | 詳細 | 上に加えて、受け付けたイベント 1 件ごと |

- 節目の記録(`mark`。起動、停止、区分の切り替え、古い区分の削除)は、`silent` 以外のどのレベルでも残す。
- `error` は `silent` 以外のどのレベルでも残す。
- レベルは表示の設定(`display`)の `diagnosticsLevel` に保存し、既存の `POST /api/display` で変える。

## 保存

- 保存先は `~/.agent-cockpit/diagnostics/` である。
- 常駐サーバーの 1 回の起動を 1 つの「起動」とし、起動ごとに区分ファイル `<起動時刻>-<pid>.<区分番号>.jsonl` に追記する。起動時刻はコロンを含まない形(`20261013T194210Z`)にする。
- 1 区分は 2000 行までで、超えたら次の区分へ移る。
- 起動は直近 10 件、区分は全体で 30 件まで残し、超えたら古いものから消す。上限で記録を止めないのは、常駐サーバーが数日動くため、止めると不具合の直前の記録が欠けるからである。
- 書き込みは 1 本の追記の流れにまとめ、行の順序を保つ。
- 1 行は `{ ts, level, tag, msg, data }` の JSON である。`tag` は出どころ(`server`、`hook`、`mcp`、`web`、`gh`、`merge`、`codex`)、`msg` は記録の識別子、`data` は識別子ごとに許した鍵だけの浅いオブジェクトである。文字列の値は 200 文字で切る。

## 受け口と許可一覧

- 常駐サーバーの中の記録は、記録の関数を直接呼ぶ。
- フックは、既存の `POST /api/events` のイベントに `diagnostics` の配列を添える。送れるのは送信の前に分かる段(標準入力の解釈、Codex のプロセス ID の照会の結果と所要時間、常駐サーバーを起動したかどうか)だけである。届いた時刻と `hookAt` の差は、常駐サーバーが記録する。
- フックが常駐サーバーに届かなかったとき(停止中、二重起動の衝突、時間切れ)は、`~/.agent-cockpit/diagnostics/hooks-pending.jsonl` に 1 行だけ追記する。成功したときはこのファイルに触らない。大きさが上限を超えたら追記しない。常駐サーバーが起動時と定期の走査で取り込み、取り込んだ分を消す。
- MCP と画面は、新しい `POST /api/diagnostics` で送る。MCP は起動ごとの秘密値、画面は `uiSecret` と同一 Origin で照合する。
- 常駐サーバーは、外から届いた記録の `msg` を既知の識別子の一覧と照合し、一覧に無いものは捨てる。`data` は識別子ごとの許可一覧の鍵だけを残す。

## 読み出しと削除

- `GET /api/diagnostics` は起動の一覧、`GET /api/diagnostics?run=<起動>` はその起動の記録を返す。`/api/state` と同じく認証を求めない。返す内容は、`/api/state` が既に出している情報(プロダクト名、PR 番号、セッション ID の先頭)を超えない。
- 削除は `POST /api/diagnostics/delete`(`uiSecret` と同一 Origin)で、選んだ起動か全件を消す。起動の識別子は形式を検査し、`diagnostics` の外のファイルに触れない。
- コピーと書き出しは画面の中で行い、常駐サーバーに外へ送る口を作らない。

## 画面

- 設定画面の「マニュアル」のリンクの右に「診断ログ」のリンクを置く。押すと診断ログのダイアログを開く。
- ダイアログには、レベルの選択、起動の選択(先頭が現在の起動)、出どころの絞り込み、更新、コピー、選んだ起動の書き出し、全起動の書き出し、選んだ起動の削除、全件の削除、ポリシーの確認を置く。
- 時刻は端末の地域の時刻で表示し、新しい記録を下に並べる。
- 書き出しの先頭には、版、レベル、起動の識別子、書き出した時刻を書く。
- 削除は、既存の「記録を削除」と同じく、確認の文と「削除する」「やめる」を出してから行う。
- ポリシーのダイアログは、外へ送らないこと、保存先と保持の上限、レベルごとの例、記録しない情報、記録する情報を、利用者の言葉で書く。

## `server.log`

- `server.log` は、常駐サーバーの標準出力と標準エラーの受け皿として残し、診断ログには吸収しない。未捕捉の例外の文に、記録しない情報が混ざりうるためである。
- 起動のたびに空にせず追記する。起動時に大きさの上限を超えていたら `server.log.1` に移す。二重起動が失敗しても、稼働中の常駐サーバーの記録は消えない。

## 最初に記録すること

過去の調査で欲しかった情報から、効果の大きいものを入れる。

1. 常駐サーバーの起動情報(pid、ポート、版、ソースの commit)
2. 失敗した要求(メソッド、ID を伏せた経路、状態、`error.code`、秘密値と Origin の照合の結果)
3. 常駐サーバーが受けたイベント(受け付けた 1 件は `debug`。採らなかったもの、遅れが閾値を超えたもの、セッションの開始と終了は `info`。イベント名ごとの受付件数を 10 分ごとに `info` の 1 行にまとめる)
4. `gh` の失敗(操作、リポジトリと PR 番号、元の登録のセッション、失敗の分類、終了コード、連続の回数)
5. マージの予約と実行(満たさない条件、head の照合の結果、`gh` の結果の分類)
6. セッションの終了の判定(Codex のロックの消失、プロセスの生死、`SessionEnd`)
7. クロスレビューの状態の読み取り(状態ファイルの有無、head の一致)
8. フックの段ごとの結果(Codex のプロセス ID の照会の結果と所要時間、届かなかった失敗)
9. MCP の書き込みの試行と結果
10. 画面の取得と保存の失敗(状態と経路名)

## 常駐サーバー内の記録

識別子ごとの鍵は `src/server/diagnostics.js` の `ALLOWED_DATA` を正本とする。
常駐サーバー内からの記録は応答処理で待たず、診断ログを渡していない場合も本体の処理を続ける。

| 識別子 | 出どころ | 記録すること |
|---|---|---|
| `event.accepted` | `server` | 採用したイベントの種類、provider、ツール名、セッション ID の先頭、プロダクト名、受付の遅れ。`debug` で残す |
| `event.rejected` | `server` | 検査、provider の不一致、委譲済み、削除済み、終了済み、古い時刻による不採用。`info` で残す |
| `event.delayed` / `event.lifecycle` | `server` | 5000 ms を超える遅れ、セッションの開始と終了。`info` で残す |
| `event.summary` | `server` | イベント名ごとの採用件数を浅いオブジェクトにまとめ、10 分ごとに `info` で残す。集計後に件数をリセットする |
| `gh.failed` | `gh` | 操作、リポジトリ、PR 番号、登録セッション ID の先頭、失敗分類、code、signal、終了コード、連続失敗回数。`error` で残す |
| `merge.check` | `merge` | 予約と実行で満たさなかった条件の分類と、head の `match` / `mismatch` / `missing`。`info` で残す |
| `merge.reserved` / `merge.cancelled` | `merge` | 保存した予約と取り消しのリポジトリ、PR 番号。`info` で残す |
| `merge.result` | `merge` | gh の成功・失敗と、マージ済み・キュー待ち・未マージの分類。失敗は `warn`、それ以外は `info` で残す |
| `session.ended` | `server` / `codex` | `SessionEnd`、Codex のプロセス終了とロック消失、セッション一覧からの消失による判定。`info` で残す。ロック消失は、ロックが戻るまで 1 回だけ残す |
| `review.state` | `merge` | 状態ファイルの `present` / `missing` / `unknown`、レビュー済み head と収束判定の head の照合、回数、判断結果、失敗分類。失敗は `warn`、それ以外は `info` で残す |

gh の連続失敗回数は操作・リポジトリ・PR 番号ごとに数え、同じ組み合わせの成功でリセットする。
API 操作は設定取得、比較、head 取得、PR 取得、ブランチ削除の種類で区別する。
失敗の分類にはエラー文と標準エラーを使わず、code、signal、タイムアウトの結果だけを使う。

クロスレビューは、登録先と探索した各 worktree の読み取り結果が変わったときだけ記録する。
ファイルの不在と、読めずに有無を確認できない状態を区別し、ファイルのパスと本文は残さない。
マージ予約の条件待ちも、満たさない条件が変わったときだけ記録する。
イベントの集計タイマーは `unref` し、常駐サーバーの `close` で止める。

## 参考元との違い

| 参考元 | agent-cockpit | 理由 |
|---|---|---|
| IndexedDB に保存 | 常駐サーバーがファイルに追記 | 記録の大半が常駐サーバーとフックで起きる |
| 1 起動 2000 件を超えたら古い順に消す | 2000 行の区分に分け、区分ごとに古い順に消す | 追記だけで古い記録を消すため |
| メモリのリングバッファ 500 件 | 持たない | 現在の区分ファイルを読めば足りる |
| レベルを localStorage と URL で指定 | 表示の設定に保存 | 記録するのは常駐サーバーである |
| 共有(Web Share)、console への同時出力 | 持たない | デスクトップの内部ブラウザと常駐サーバーでは使わない |
| 文字数の上限やマスクは無い | 受け口で識別子と鍵を選び、文字列を 200 文字で切る | 会話の本文と秘密値を扱うため |
