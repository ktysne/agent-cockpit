# 質問と指示の合成行の状態表示

GET /api/stateが質問と指示の投影だけから新しく作る行に、検証済み登録実行の観測状態を表示する。
既存state行のstatus、title、product、IDは上書きしない。
登録、配信、writerの認可へ書き戻さず、物理プロセスの停止確認にも使わない。

## 応答と集約

新規合成行だけに`projectionOnly: true`を追加する。
これは当該応答の質問と指示だけから構成した行という公開応答契約であり、保存schemaには追加しない。
後続の応答に実state行が現れれば、この属性を付けない。

既存のprovider出自と表示墓標のguardを通ったvalidated linkについて、同じexecutionIdとstateが一致する場合だけその状態を採用する。
activeは待機中、endedは終了済み、unknownは不明と表示する。
異なるexecutionId、状態の不一致、未知のstateは不明とし、同じ応答で後続の一致値から復帰させない。
二つのserviceのsnapshotは別時点であり、応答送信時点の最新状態を保証しない。

新たなregistry snapshotや全履歴cloneを追加しない。
受理した投影に一回ずつ集約し、新規合成行のMapを応答内で共有する。
既存のリンク検証自体の走査コストを改善したとは扱わない。
質問snapshot失敗は利用できる質問投影がない状態であり、全行のunknown観測へ置き換えない。
指示unknownは既存validatorでunmatchedになるため、その条件を緩めない。
終了時刻を取得していないのでendedAtは生成しない。

## 画面と操作

終了済みは専用のラベルと静止した点で表示する。
「終わったものを非表示」の判定は、待機中と同様に全タスク、判断事項、質問、指示が終端であることを必要とする。
終了statusだけで未解決カードを隠さない。
不明の合成行には実state行が必要な「状態を推定」を出さず、投影の「一覧から外す」は維持する。
回答と指示の送信可否、件数、宛先IDは既存の個別条件を維持する。

モックにも合成行の終了と不明の限定例を置く。
UX状態レビューの完了表示規則を適用し、読み込み、入力、保存、削除の新しい操作は追加しない。
行の保持を暫定採用するが、親配置、conversation単位の統合、titleとproductの供給元は別の判断として残す。

## 検証境界

両providerで質問active/ended/unknown、指示active/ended、unknown指示のunmatched、複数投影の不一致と順序、実rowへの合流を確認する。
出自混在、hidden/deleted、質問service失敗と有効な指示の組合せを維持する。
画面fixtureでは終了ラベル、未解決カードの保持、不明合成行の推定操作抑止、実不明行の推定維持を確認する。
fixtureとモックを実provider runtime、親子の相関、resume統合、物理停止の証拠として扱わない。
