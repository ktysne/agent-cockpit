離席中

離席中は、席を外している間に出た質問への回答を、決めた時間だけ待たせる機能です。 推奨案を示した質問は、回答が無いまま締切を過ぎると、その案で作業を進めます。 戻ったあとは、離席中に起きた変化を「前回見てから」で確かめられます。

席を外す前から戻ったあとまでの流れは、席を外している間に判断を返すで順に説明しています。

離席中の切り替え

席を外すときに、ヘッダの右上の 離席中 にチェックを入れます。 タスクトレイのメニューにも、同じ名前の項目があります。 どちらで切り替えても、同じ状態が反映されます。

離席中にすると、次のように変わります。

  • メインセッションの AskUserQuestion と、ask 付きの mcp__ccd_turn__wrap_up を、ダッシュボードの回答を待って預かります(離席中の質問)
  • セッションを開始したときと、プロンプトを送るたびに、開発者が離席中であることを Claude Code と Codex のセッションに伝えます。セッションは、開発者に尋ねずに推奨を適用して作業を続け、破壊的な操作は行わず、判断待ちとして最後の報告に書きます
  • 離席中の期間が記録され、「前回見てから」に使われます(前回見てから)
ツールの実行許可は、離席中も、Claude Code または Codex の元の画面で出す必要があります(許可待ち)。

離席中の状態は常駐サーバーが保存するので、常駐サーバーを再起動しても残ります。 切り替えに失敗したときは、チェックを元に戻し、離席中を切り替えられませんでした と出ます。

離席中の質問

離席中に Claude Code のメインセッションが AskUserQuestion を使うと、質問のダイアログをデスクトップアプリに出さず、ダッシュボードの回答を待ちます。 mcp__ccd_turn__wrap_up に ask を付けたときも、同じように回答を待ちます。 質問は、判断事項のカードに回答欄つきで出ます。 待つ時間は、設定の 離席中に質問の回答を待つ時間 (1〜30 分) で決めます(離席中に質問の回答を待つ時間)。 既定は 3 分です。

Codex のメインセッションの質問も、同じ時間だけダッシュボードの回答を待ちます。 回答を待つ間は、元の画面に質問を出しません。 待ちをやめて質問を通すと、Codex の元の画面に出ます。 Codex が自分で起動したサブエージェントの質問は預かりません。

締切までに回答を送ると、その回答が質問への答えとして渡されます。 回答の操作と、渡った後の表示は、判断事項のページで説明しています(ダッシュボードから回答する)。

設定を変えても、すでに預かっている質問の締切は変わりません。 新しい時間は、次に出る質問から効きます。

離席中の質問の詳細
  • 回答を待つ途中でセッションが中断すると、判断事項は取り下げになります
  • Claude のサブエージェントと、Codex が自分で起動したサブエージェントが出した質問は、預からずに止め、推奨を適用して進めるようにサブエージェントへ伝えます
  • 同じ質問の文が 2 つ以上含まれる質問は、預からずに、Claude Code または Codex の元の画面に出します
  • 質問を預かる仕組みは、対話のセッションでだけ働きます。claude -p のような非対話の実行では、質問のツールが使えないため、預かる質問がありません
  • 残り時間は、分に切り上げて出します
  • 質問を預かるフックは、待つ間、常駐サーバーに 25 秒ごとに確認します(常駐サーバーと連絡が取れないとき)

回答が無いまま締切を過ぎたとき

締切までに回答が無いと、質問を止めて、推奨案で作業を続けるようセッションに伝えます。 mcp__ccd_turn__wrap_up では、actions の先頭を推奨として返します。 選択肢が無い場合は推奨を作らず、判断待ちとして最後の報告に書いて作業を続けるよう伝えます。 セッションは破壊的な操作をせず、判断が必要だった事項と、仮に適用した推奨があれば最後の報告に書きます。

wrap_up への回答と時間切れの結果は、ツールを拒否する理由としてセッションに返ります。 作業を終えたら、ask を付けずに wrap_up を呼び直します。

Codex の選択肢の無い質問は、締切後に仮定を置いて自分の判断で進めるよう伝えます。 判断事項は 仮に推奨案で進行中 に変わり、経過時間は 仮適用から の形で出ます。

戻ってから送った回答は、質問への答えではなく、作業への指示として、セッションに届きます(回答が届く経路)。 セッションは、回答に沿って作業を直します。 Codex は、次のツールの実行後か次の入力で受け取ります。 離席中にターンが終わったときだけ、最大 59 分待って届けます(回答が届く経路)。 離席中を解除すると、Codex のターン終了後の待ちもやめます。

離席中を解除したとき

Codex では、離席中を解除すると質問の待ちをやめ、質問を元の画面に出します。

Claude Code では、離席中のチェックを外すと、預かっていた質問の待ちをやめ、質問のダイアログをデスクトップアプリに出します。 判断事項は 止めて待っている のままで、回答欄と残り時間は消えます。 デスクトップアプリで答えます(デスクトップアプリで答える判断事項)。

回答を送っていない wrap_up の ask もダッシュボードでの待ちをやめ、元の入力のままツールを続けます。

締切より前に送った回答があるときは、離席中を解除していても、その回答を質問への答えとして渡します。

常駐サーバーと連絡が取れないとき

質問を預かるフックは、待つ間、常駐サーバーに繰り返し確認します。 待ちが終わるときには、結末を知らせる終わりの通知を送ります。 常駐サーバーを再起動したときや、止まったときは、通知や確認が届かないことがあります。

  • 終わりの通知が常駐サーバーに届いたとき：回答があれば、その回答を渡します。回答が無ければ、離席の状態を確かめます。離席中のままなら、質問を止めて推奨案で進めます。解除されていれば、質問のダイアログをデスクトップアプリに出します
  • 終わりの通知も届かなかったとき：フックは離席の状態を確かめられないので、いつも質問を止めて推奨案で進めます
  • 常駐サーバーが、フックからの確認を 30 秒受け取れなかったとき：預かりをやめ、その判断事項に送っていた回答を破棄します。回答欄は消え、判断事項はデスクトップアプリで答える状態に戻ります
終わりの通知の詳細

終わりの通知は、内部では finish と呼びます。 通知が届いても、常駐サーバーが再起動して預かりの記録を失っていたときは、離席の状態だけを確かめて、離席中なら推奨案で進めます。 このとき、判断事項は 仮に推奨案で進行中 になります。

常駐サーバーを再起動しても、送信済みで渡していない回答は残ります。 ただし、預かりが切れるので、次のプロンプトの送信か、ツールの実行のひと区切りまで渡りません(回答が届く経路)。

前回見てから

離席中の期間に起きた変化を、プロダクトごとにまとめて出す欄です。 変化があるプロダクトのカード内に、設定の欄の並び順に従って出ます(プロダクトのカード)。 種類別の表示では、前回見てから の欄になります(プロダクト別と種類別の違い)。

変化には、次の種類があります。

  • タスクが完了した(画面で完了にしたタスクを含みます)
  • PR を作成した、PR をマージした、PR の CI が失敗した。1 つの PR の変化は、「PR #115(題)を作成し、マージした」のように 1 件にまとめます
  • 判断を推奨案で仮に進めた

出るのは、次の両方を満たす変化です。

  • 離席中の期間に起きた変化。離席中なら、いまの時刻までを含みます
  • そのプロダクトを最後に既読にした時刻より後の変化

離席中を解除しても、既読にするまで、変化は残ります。 既読にしていないプロダクトは、初めて一覧に出た時刻を、既読にした時刻として数えます。 既読にする を押すと、そのプロダクトの判断事項の 新着 の印も外れます。

未読のプロダクトが 2 つ以上あるときは、すべて既読にする でまとめて片付けられます。

離席中の期間の記録の詳細

離席中の期間は、開始と終了の時刻を記録します。 記録は、最大 50 件までで、14 日を過ぎた期間は消します。 すべてのプロダクトを既読にした後は、その前に終わった期間も消します。

前回見てからの表示の設定

「前回見てから」を出すかどうかは、設定の 前回見てから で選びます。 設定の画面は、ヘッダの歯車のボタンで開きます(ヘッダ)。

  • 表示する：離席中に起きた変化を既読にするまで出します。初期設定です
  • 表示しない：出しません

この設定は表示だけを切り替えます。 変化の記録は、どの設定でも続きます。 設定はブラウザごとに保存するので、別のブラウザには引き継がれません。
