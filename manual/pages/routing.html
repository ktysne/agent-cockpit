経路の設定

経路の設定は、サブエージェントとクロスレビューを、Codex と Claude のどちらで行うかを選ぶ欄です。 画面の上部にあり、全セッションに共通です。 サブエージェントの経路は Claude のセッションが起動する bridge の窓口(impl-hard、impl-standard、impl-light、codex-subagent)に効きます。 codex-review はクロスレビューの経路に従い、Codex が自分で起動したサブエージェントにはどちらも効きません。 変えた設定は、次に起動する対象の窓口と、次に始めるクロスレビューから効きます。

選べる経路

サブエージェントとクロスレビューのそれぞれに、既定、Codex、Claude の 3 つから 1 つを選びます。 押したボタンがすぐ保存され、選んでいるボタンが色付きで出ます。

経路の意味は、サブエージェントとクロスレビューで少し違います。

  • 既定：経路を指定しません。bridge の窓口にもクロスレビューにも、何も伝えず、止めもしません。選び直さなければ、この状態です
  • Codex：bridge の窓口には、Codex へ委譲して作業するよう、起動時に伝えられます。クロスレビューは、Codex をレビュアーにします
  • Claude：bridge の窓口には、Codex へ委譲せずに Claude 自身で作業するよう、起動時に伝えられます。クロスレビューは、Claude をレビュアーにします

サブエージェントの経路は、Claude のセッションが起動する claude-codex-bridge の窓口に対する指定です。 codex-review はサブエージェントの設定ではなく、クロスレビューの設定に従います。 Claude を選んだ対象の窓口が Codex を呼び出そうとすると、フックが止めます。 止められた窓口は、Claude 側で実装する担当への委譲し直しを、メインセッションに報告します。

クロスレビューの経路は、ai-cross-review が、レビューを始める直前に読みます。 Codex か Claude を選んでいるのに、違うレビュアーで始めようとすると、ai-cross-review は始めずに断ります。 会話で別の指定があるときは、ai-cross-review のオプションで、理由を添えて上書きできます。

経路の動きの詳細
  • route.js は impl-hard、impl-standard、impl-light、codex-subagent ではサブエージェントの設定を、codex-review ではクロスレビューの設定を開始時に追加の文脈として渡します。その他の agent_type は対象外です。Claude の経路を記録した窓口では、Codex を呼ぶコマンドをツールの実行の直前に断ります。このフックを登録していないと、経路の札は付きますが、窓口には伝わりません(導入手順書のパターン C)
  • クロスレビューの経路は、node tools/cross-review.js route が、常駐サーバーの保存先の routing.json を読んで、codex、claude、default のどれかを出力します。ファイルが読めないときは default です
  • 常駐サーバーは、routing.json が無いとき、壊れているとき、値が不正なときは、両方を 既定 として扱います。ほかのプログラムがファイルを開いているなどで読み直しても読めないときは起動せず、route.js のフックはサブエージェントに何も渡しません
  • claude-codex-bridge の窓口が Claude の指定を受けたときの動きは、claude-codex-bridge 側の Issue 129 で扱っています

欄が出る条件

経路の設定の欄は、連携ツールを入れているときだけ出ます。 段ごとに条件が違います。

  • サブエージェント の段：claude-codex-bridge を入れているときです。Claude のホーム(環境変数 CLAUDE_CONFIG_DIR、無ければ ~/.claude)か ~/.claude の tools/ に、codex-agent.sh があれば入っているとみなします
  • クロスレビュー の段：ai-cross-review を入れたリポジトリを、画面が知っているときです。動いているセッションの作業ディレクトリか、PR を登録したセッションの作業ディレクトリのどれかで、作業ツリーのルートに tools/cross-review.js があれば出ます

片方だけのときは、その段だけが出ます。 どちらも無いときは、欄ごと出ません。 連携ツールを入れても外しても、画面を開き直さなくても、遅くとも 1 分ほどで欄が出入りします。

連携ツールが無くても、Agent Cockpit はエラーも警告も出さずに動きます(連携ツールの有無で変わる表示)。

効く時点

経路の設定は、ボタンを押した時点で常駐サーバーの routing.json に保存されます。 保存できなかったときは、経路の設定を保存できませんでした。 と出て、ボタンは元の選択のままです。

変えた設定は、次のものから効きます。

  • bridge の窓口：設定を変えた後に Claude セッションが起動するものから。稼働中の窓口は、止めも、切り替えもしません
  • クロスレビュー：設定を変えた後に始めるレビューから
サブエージェントの経路の記録の詳細
  • bridge の窓口は「サブエージェント」の値を、codex-review は「クロスレビュー」の値を開始時に読み、「既定」を含めて route-agents/ に記録します。「既定」の場合は文脈を差し込まず、Codex の起動も拒否しません
  • 同じサブエージェントが再開したときも、最初の記録の経路のままです
  • 記録は、読むたびに更新時刻を進めます。24 時間使われていない記録は、新しいサブエージェントの開始時に削除します

経路の札と「変更前」

claude-codex-bridge を入れているときは、Claude セッションが起動した対象の窓口と、「クロスレビュー」の経路(既定、Codex、Claude のどれでも)で動く codex-review の稼働中の行に、起動したときの経路が 経路: の札で出ます。 起動した後で経路の設定を変えると、いまの設定と違う札に (変更前) が付きます。 札は、稼働中のサブエージェントが、いまの設定とは別の経路で動いていることを示します。

札にマウスを載せると、起動時に効いていた経路の設定 と出ます。 行のほかの札の見方は、サブエージェントのページにあります(経路の札)。
