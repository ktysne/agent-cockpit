判断事項と回答

判断事項は、セッションが開発者に決めてほしいと求めた事項です。 あなたの判断が必要なこと の欄に、カードとして並びます。 このページでは、カードの見方と状態、ダッシュボードからの回答の操作、回答がセッションへ届く経路を説明します。

判断事項の元

判断事項は、次の質問や記録から作られます。

  • Codex の質問ツール(request_user_input_async、Plan モードの request_user_input)で出した質問
  • Claude Code のメインセッションが、質問のツールで開発者に尋ねた質問。フックが自動で判断事項にします
  • メインセッションが、Agent Cockpit のツール(cockpit_add_decision)で記録した判断。開発者に確認中の判断と、推奨案を仮に適用して進めた判断を残すのに使います

判断事項のカード

カードの左端の色は、状態を示します。 止めて待っているものは赤、仮に進めているものは琥珀色、解決済みは緑、取り下げは灰色です。 カードにマウスを載せると、判断事項の id が出ます。 id は、セッションが判断事項を更新するときに使う値です。

判断事項の状態

  • 止めて待っている：開発者への質問が出ていて、回答を待っています。
  • 仮に推奨案で進行中：回答を待たず、推奨案を仮に適用して作業を進めています。離席中の質問が回答の無いまま締切を過ぎたときも、この状態になります(締切を過ぎたとき)。
  • 解決済み：答えが決まりました。選んだ内容と理由が、カードの下に 選択: の形で出ます。
  • 取り下げ：質問が答えられないまま終わりました。質問のツールが成功せずに終わったときです。

解決済みと取り下げのカードは、設定の 終わったものを非表示にする がオフのときだけ、解決済みと取り下げ の開閉ボタンから開けます。 オン(既定)のときは出ません。

経過時間と強調

経過時間の出し方は、状態で変わります。

  • 止めて待っている判断事項は、作られてからの時間が 待機中 の形で出ます。設定の時間(既定 15 分)を超えると、カードの背景が赤みを帯び、時間が太い赤の文字になります。時間は設定の 長く待たせているとみなす時間 (1〜120 分) で決めます
  • 離席中に出た質問には、続けて「あと 3 分で推奨に進む」の形で、推奨案で進むまでの残り時間が出ます(離席中の質問)
  • 仮に進めている判断事項は、仮適用から の形で出ます。この状態の判断事項は、長く待っていても強調しません

回答を送った判断事項は、強調しません。 また、画面上部の 止めて待っている と 仮に推奨案で進行中 の件数と、プロダクトのカードの 判断待ち の件数にも数えません(件数の札)。 セッションの見出しの あなたの判断が必要なこと の件数には、回答を送ったものも数えます。

仮適用からの時間の詳細

仮に進めている判断事項の時間は、仮適用になった時刻から数えます。 回答を送ったときや、回答がセッションに渡ったときも、数え直しません。 仮適用になった時刻を記録していない古い保存データの判断事項だけは、判断事項を最後に更新した時刻から数えます。

推奨の判定

Codex のすぐ戻る質問(request_user_input_async)は、先頭の選択肢を推奨にします。 選択肢の無い質問には、指示だけで答えます。 待つ質問(request_user_input)と Claude Code の質問の推奨は、質問ごとに、次の条件をすべて満たすときに決まります。

  • 選択肢を 1 つだけ選ぶ質問である(複数選択の質問は、推奨なしです)
  • 選択肢の名前に (推奨)、（推奨）、(Recommended)、（Recommended） のどれかを含むものか、判断の記録で推奨と明示したものが、ちょうど 1 つである

括弧は、全角か半角のどちらかにそろえます。 英語の大文字と小文字は区別しません。 選択肢の説明は、判定に使いません。 推奨と判定した選択肢には 推奨 の札が付き、名前から (推奨) などの文字を取り除いて表示します。

デスクトップアプリで答える判断事項

回答欄が無く、選択肢を押せない判断事項は、デスクトップアプリで答えます。 上の図のカードが、その例です。 カードの最下段に書いてあるプロダクトとセッションを、デスクトップアプリで開きます。 質問のダイアログが出ていればダイアログで、出ていなければセッションの入力欄で答えます。

次の判断事項が、これに当たります。

  • 離席中でないときに出た質問。質問のダイアログは、デスクトップアプリに出ています
  • セッションが 止めて待っている として記録した判断
  • 同じ質問の文が 2 つ以上含まれる質問。回答を質問に対応づけられないためです

ダッシュボードからは、これらの判断事項に回答を送れません。 Claude Code の質問のダイアログに答えると、質問のツールが終わり、判断事項は 解決済み になります。 セッションが記録した判断は、セッションが解決済みに更新したときに 解決済み になります。

Codex の在席中の質問は、Codex の元の画面で答えます。 すぐ戻る質問は、その会話への次の入力で 解決済み になり、「元の画面で回答済み(内容は不明)」と出ます。 質問と無関係な入力でも閉じます。 待つ質問は結果が届いたときに解決済みになり、結果が届かないまま次の入力があると 取り下げ になります。

ダッシュボードから回答する

回答欄が出るのは、次の判断事項です。

  • 仮に推奨案で進行中 の判断事項
  • 離席中に出た質問のうち、回答を待っているもの(離席中の質問)

回答の組み合わせは、次のとおりです。

  • 推奨を受け入れる場合も、推奨 の札が付いた選択肢を選んで送ります
  • 選択肢を選んで送る。複数の質問がある判断事項で、選ばなかった質問は、推奨があれば推奨の選択肢で、無ければ指示で答えたことになります。推奨も指示も無い質問が残る間は、送れません
  • 指示だけを書いて送る
  • 上のどれかに、指示を添えて送る

回答は、送った後で変えて送り直せます。 最新の回答が有効になり、渡した時刻と反映された時刻はやり直しです。 送った回答から何も変えていないときは、回答を送る は押せません。 変えた内容を送っていないときは、送信の状態に 変更は未送信 と出ます。

入力の途中の内容は、ページを開き直すと消えます。 送った回答は、ページを開き直しても残ります。

回答欄のエラーの詳細

送れなかったときは、回答欄の下に理由が出ます。

  • 判断事項の状態が変わりました。表示を確認してください。：送る前に、判断事項が解決されたか、回答を受け付けない状態になっています
  • 回答の選択内容と指示を確認してください。：選択肢が質問に合っていないか、推奨も指示も無い質問が残っています
  • 回答を送信できませんでした。：常駐サーバーに送れませんでした

日本語の入力で変換している間は、画面の描き直しを待ち、入力が確定してから描き直します。

回答がセッションへ届くまで

送信済み、渡した、反映された

回答を送ると、回答欄の下に、届き具合が時刻つきで増えていきます。 時刻は、同じ日なら「14:00」の形で、別の日なら日付が付きます。

1. 送信済み：ダッシュボードが回答を受け付けると、送信済み と、回答の種類が出ます。 種類は、選んだ選択肢の名前に を選択 を付けたものか、指示のみ です。 以前に送った回答は、保存済みの種類として 推奨案で OK と表示される場合があります。 指示を添えたときは、(指示あり) が付きます。

2. 渡した：回答をセッションに渡すと、に渡した と、渡した時刻が続きます。

3. 反映された：セッションが回答を受けて判断事項を更新すると、に反映された と、反映された時刻が続きます。

仮に進めている判断事項では、セッションが判断事項を更新したときに、反映されたことになります。 離席中の質問では、質問のツールが回答つきで終わったときです。

回答が届く経路

回答は、セッションの状態に合わせて、次のどれかの経路で届きます。 どの経路でも、渡した時点で に渡した が付きます。

  • 離席中に待っている質問への回答：質問を待っているフックが受け取り、質問の答えとして渡します。デスクトップアプリに質問のダイアログは出ません(離席中の質問)
  • セッションが作業中のとき：ツールの実行がひと区切りしたところで、回答の文をセッションに差し込みます
  • Claude Code のセッションが待機中のとき：待機中のセッションに回答を渡し、作業を再開させます
  • 開発者が新しいプロンプトを送ったとき：渡した回答がまだ反映されていなければ、プロンプトに添えて渡し直します。渡し直しは最大 3 回までです

Codex は、作業中なら次のツールの実行後に回答を受け取ります。 在席中は、ターンの終わりに未配信の回答があれば一度だけ続行します。 ターンが終わった後に回答が届いても、セッションを起こせないので、次の入力か次のツールの実行後に届きます。 離席中にターンが終わったときは、回答や通知を最大 59 分待って届けます。 待つ間は Codex の画面が作業中になり、Esc で中断できます。 離席中を解除すると待つのをやめます。

回答が届く経路の詳細

経路は、セッションのフックで実現しています。

  • 質問への答え：質問のツールを実行する直前のフック(PreToolUse)が、質問に答えを加えて返します。元の質問の内容は変えません
  • 作業中の差し込み：ツールのまとまりが終わるときのフック(PostToolBatch)が、回答の文を渡します
  • 待機中の起こし：ターンの終わりのフック(Stop)が、非同期で回答を待ちます。回答が届くと、標準エラーに書いて終了コード 2 で終わり、セッションを起こします。待つ間は、常駐サーバーに最大 25 秒ずつ尋ねます
  • 渡し直し：プロンプトの送信のフック(UserPromptSubmit)が、反映されていない回答を渡し直します

Codex では、次の点が違います。

  • 質問への答え：Codex の質問のツールには答えを加える入力が無いので、実行する直前のフック(PreToolUse)が質問のツールを止め、止めた理由に回答を書いて返します。返した時点で判断事項は解決済みになります
  • 作業中の差し込み：PostToolBatch が無いので、ツールが 1 つ終わるたびのフック(PostToolUse)が渡します
  • 待機中の起こし：ターンの終わりのフック(Stop)が待つのは離席中だけで、届いた回答で続行させます。在席中は、ターンの終わりに未配信の回答があれば一度だけ続行させます

渡す回答の文には、判断事項の id と題、回答の種類、指示が入ります。 セッションは、回答に沿って作業を直し、判断事項を更新します。

回答の種類ごとに、質問への答えは次のとおりです。

  • 推奨の選択肢を選んだ回答：選んだ選択肢の名前を答えにします。指示があれば、追加の文脈として添えます
  • 選択肢を選ぶ：選んだ選択肢の名前を答えにします。複数選択で複数を選んだときは、名前を「, 」でつないだ 1 つの文字列にします。選ばなかった質問は、推奨の名前、無ければ指示の文を答えにします
  • 指示のみ：指示の文を答えにします

離席中に待っている質問の回答は、質問を待つフックだけが受け取ります。 作業中の差し込み、待機中の起こし、渡し直しの対象にはなりません。

閉じたセッションには、回答は届きません。
