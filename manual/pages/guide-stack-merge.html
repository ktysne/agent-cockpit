積み上げた PR を順にマージする

前の PR のブランチを base にして積んだ PR は、スタックの一番下から順にマージします。 このページでは、スタックの表示を読み、一番下の PR がマージできる条件を確かめて、確認欄でマージするまでを説明します。 レビューが済んでいない PR にはマージの予約を使い、マージのあとは、結果と積み直しの依頼を確かめて次の PR へ進みます。 各手順の細かな仕様は、手順の最後のリンク先で説明します。

このページでできるようになること

  • スタックの表示から、どの PR をいまマージできるかを読み取る
  • 一番下の PR について、マージできる条件が残っていないかを確かめる
  • 確認欄でマージの方式を選び、マージする
  • レビューの収束を待ってマージするよう、予約する
  • マージの結果と積み直しの依頼を確かめて、次の PR へ進む

必要なもの

  • 認証済みで使える GitHub CLI(gh)(連携ツールの有無で変わる表示)
  • セッションに登録した PR(PR の登録)

スタックの表示を読む

PR は、プロダクトのカードの プルリクエスト の欄に、リポジトリごとの枠で並びます。 この例では、プロダクト parcel-api の PR #41、#42、#43 が、3 段のスタックになっています。

  1. リポジトリの枠を見つける枠の見出しに、リポジトリ名と、マージできる PR の件数が出ます。 スタックの土台の main の横に、「スタック 3 段」と段数が出ます(スタックの表示)。
  2. 下から数える一番下の PR #41 の位置の札は「1/3」で、直上の #42 が「2/3」、その直上の #43 が「3/3」です。 マージする のボタンが付くのは、一番下の #41 だけです。 #42 には「マージできない理由: 下の #41 のマージ待ち」と出ます。 一番下以外の PR は、下の PR がマージされるまで、マージできません(マージできない理由と待ち)。

一番下の PR がマージできる条件を確かめる

一番下の PR は、状態の札が マージできます か マージ操作は可能 になっています。 マージできます は、設定で選んだ条件まで満たしている PR です(「マージできます」の条件)。

  1. 条件がそろっているかを確かめるPR #41 には マージできます が出ています。 CI 成功、承認済み、クロスレビューの レビュー済み がそろっているためです。 既定の設定では、CI とクロスレビューが済んでいる PR に マージできます を出します(「マージできます」と出す条件)。
  2. 条件が残っているときの表示を知る別のリポジトリの PR #118 は、マージ操作は可能 のままです。 CI 実行中 で、クロスレビューも対応中のため、待ち: の行に満たしていない条件が出ます。 この PR も、確認欄から手でマージできます。 その場合、確認欄の先頭に、満たしていない条件の警告が出ます(マージできない理由と待ち)。

確認欄で方式を選んでマージする

マージは取り消せません。 方式、ブランチの削除、警告、照合する head SHA を読んでから、マージを実行 を押します(マージする)。
  1. 確認欄を開くPR #41 の マージする を押します。 PR の行の下に、「#41 を main へマージする」という確認欄が開きます。 やめる を押すと、何もせずに閉じます。
  2. 方式とブランチの扱いを選ぶマージの方式を、マージコミット、スカッシュ、リベース から選びます。 リポジトリで許可されている方式だけが出ます。 ここでは スカッシュ を選びます。 マージ後にリモートブランチを削除する は、入れておくと、マージのあとに PR のブランチを GitHub から削除します。 すぐにはマージせず、予約したいときは レビュー収束後マージ を入れます(レビュー収束後マージを予約する)。
  3. 警告と照合する SHA を確かめて実行する確認欄の下の方に、照合する head SHA の 7 桁が出ます。 画面で見ている head のコミット以外は、マージしません。 スカッシュかリベースで、直上に PR があるときは、上の PR に元のコミットが残るため、セッションに積み直しを依頼する旨の警告も出ます。 確かめたら マージを実行 を押します(マージの前に確かめること)。

レビューが済んでいない PR は収束後のマージを予約する

クロスレビューの最中の PR は、すぐにはマージしたくないことがあります。 レビュー収束後マージ を予約しておくと、条件がそろった時点で、常駐サーバーがマージします。 ここでは、別のリポジトリの PR #118 を例にします。

  1. 予約を入れる確認欄で レビュー収束後マージ を入れます。 見出しが「#118 を main へレビュー収束後にマージする」に変わり、ボタンが 予約する になります。 照合する head SHA は、PR の今の head ではなく、クロスレビューの収束記録になります。 方式を選んで 予約する を押します(レビュー収束後マージ)。
  2. 予約中の表示を確かめるPR の行が予約中の背景になり、マージする は 予約を取り消す に変わります。 予約中の札に、方式、予約した時刻、まだ満たしていない条件が出ます。 予約はダッシュボードを開いていなくても実行されます。 ただし、クロスレビューが止まったときや PR が閉じられたときは、常駐サーバーが予約を取り消して知らせます。その場合は理由を確かめ、必要なら予約し直します(予約が取り消されるとき)。

結果を確かめて次の PR へ進む

マージが済むと、PR の枠に結果の行が出ます。 直上の PR は、base が既定ブランチに付け替わり、新しい一番下になります。

  1. 結果の行を確かめる枠の下端に、「PR #41: スカッシュ でマージしました。ブランチを削除しました。#42 の base を main に付け替えました。」と出ます。 マージ済み (24 時間) の一覧にも、#41 が時刻と方式つきで加わります(マージの結果)。
  2. 積み直しの依頼を確かめるスカッシュでマージしたので、#42 の差分に #41 のコミットが残っています。 #42 には 積み直しが必要 の札が付き、マージできない理由は「積み直し待ち」になります。 常駐サーバーは、PR を登録したセッションに、積み直しの依頼を送ります。 マージコミット でマージしたときは、積み直しの依頼はありません(積み直し、セッションへの知らせ)。
  3. 次の PR をマージするセッションが #42 を積み直して push すると、積み直しが必要 の札が消えます。 条件がそろえば マージできます が出るので、#42 を同じ手順でマージします。 #43 も、#42 のマージのあとに、同じ流れで進めます。
