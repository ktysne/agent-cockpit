積み上げた PR を順にマージする

前の PR のブランチを base にして積んだ PR は、スタックの一番下から順にマージします。 このページでは、スタックの表示を読み、一番下の PR がマージできる条件を確かめて、確認欄でマージするまでを説明します。 レビューが済んでいない PR にはマージの予約を使い、マージのあとは、結果と積み直しの依頼を確かめて次の PR へ進みます。 各手順の細かな仕様は、手順の最後のリンク先で説明します。

このページでできるようになること

  • スタックの表示から、どの PR をいまマージできるかを読み取る
  • 一番下の PR について、マージできる条件が残っていないかを確かめる
  • 確認欄でマージの方式を選び、マージする
  • レビューの収束を待ってマージするよう、予約する
  • マージの結果と積み直しの依頼を確かめて、次の PR へ進む

必要なもの

  • 認証済みで使える GitHub CLI(gh)(連携ツールの有無で変わる表示)
  • セッションに登録した PR(PR の登録)

スタックの表示を読む

PR は、プロダクトのカードの プルリクエスト の欄に、リポジトリごとの枠で並びます。 この例では、プロダクト parcel-api の PR #41、#42、#43 が、3 段のスタックになっています。

  1. リポジトリの枠を見つける枠の見出しに、リポジトリ名と、マージできる PR の件数が出ます。 スタックの土台の main の横に、「スタック 3 段」と段数が出ます(スタックの表示)。
  2. 下から数える一番下の PR #41 の位置の札は「1/3」で、直上の #42 が「2/3」、その直上の #43 が「3/3」です。 マージする のボタンが付くのは、一番下の #41 だけです。 #42 には「マージできない理由: 下の #41 のマージ待ち」と出ます。 一番下以外の PR は、下の PR がマージされるまで、マージできません(マージできない理由と待ち)。

一番下の PR がマージできる条件を確かめる

一番下の PR は、右の列の状態が マージできます か マージ操作は可能 になっています。 マージできます は、設定で選んだ条件まで満たしている PR です(「マージできます」の条件)。

  1. 条件がそろっているかを確かめるPR #41 には マージできます が出ています。 CI 成功、承認済み、クロスレビューの レビュー済み がそろっているためです。 既定の設定では、CI とクロスレビューが済んでいる PR に マージできます を出します(「マージできます」と出す条件)。
  2. 条件が残っているときの表示を知る別のリポジトリの PR #118 は、マージ操作は可能 のままです。 CI 実行中 のため、待ち: の行に満たしていない条件が出ます。 クロスレビューの結論待ちは、クロスレビューの行の黄の札が示すので、待ち: の行には重ねて出しません。 この PR も、確認欄から手でマージできます。 その場合、確認欄の先頭に、満たしていない条件の警告が出ます(マージできない理由と待ち)。

確認欄で方式を選んでマージする

マージは取り消せません。 方式、ブランチの削除、警告、照合する head SHA を読んでから、マージを実行 を押します(マージする)。
  1. 確認欄を開くPR #41 の マージする を押します。 PR の行の下に、「#41 を main へマージする」という確認欄が開きます。 やめる を押すと、何もせずに閉じます。
  2. 方式とブランチの扱いを選ぶマージの方式を、マージコミット、スカッシュ、リベース から選びます。 リポジトリで許可されている方式だけが出ます。 ここでは スカッシュ を選びます。 マージ後にリモートブランチを削除する は、入れておくと、マージのあとに PR のブランチを GitHub から削除します。 レビューの収束を待ってマージしたいときは、確認欄を開かずに、PR の行の 収束後マージ のチェックを入れます。条件がそろっていれば、その場でマージします(レビュー収束後マージを予約する)。
  3. 警告と照合する SHA を確かめて実行する確認欄の下の方に、照合する head SHA の 7 桁が出ます。 画面で見ている head のコミット以外は、マージしません。 スカッシュかリベースで直上に PR #42 があるときは、スカッシュまたはリベースでは #42 に #41 のコミットが残るため、セッションに積み直しを依頼する。 と出ます。 確かめたら マージを実行 を押します(マージの前に確かめること)。

レビュー収束後マージを予約する

クロスレビューの最中など、条件が残っている PR は、行の 収束後マージ のチェックで予約できます。 条件がそろった時点で、常駐サーバーがマージします。 ここでは、別のリポジトリの PR #118 を例にします。

  1. 行のチェックを入れるPR #118 の 収束後マージ を入れます。 画面で見た head、選ばれているマージ方式、ブランチ削除の設定を使います。 チェックを入れた時点でサーバーが条件を取り直し、条件がすでにそろっていれば収束記録の SHA を照合してマージします。 その場合は結果の行と「PR #118 をマージしました。」が出ます。条件が残っていれば予約として保存され、「PR #118 のレビュー収束後マージを予約しました。」と知らせます。 クロスレビューが止まっている(halted)など、予約できない状態なら、その場で取り消して理由を知らせます。 予約は開発者が PR ごとに入れたときだけ作られます(レビュー収束後マージ)。
  2. 予約中の表示を確かめる予約中も マージする とチェックが表示されます。チェックは入った状態です。 予約中の札に、方式、予約した時刻、まだ満たしていない条件が出ます。 待ちの文言は予約中の札の詳細にあります。 予約はダッシュボードを開いていなくても実行されます。 ただし、クロスレビューが止まったときや PR が閉じられたときは、常駐サーバーが予約を取り消して知らせます。その場合は理由を確かめ、必要なら予約し直します(予約が取り消されるとき)。 取り消しの知らせはリポジトリの枠の先頭に出て、1 分たつか同じ PR を予約し直すと消えます。

結果を確かめて次の PR へ進む

マージが済むと、PR の枠に結果の行が出ます。 直上の PR は、base が既定ブランチに付け替わり、新しい一番下になります。

  1. 結果の行を確かめる枠の下端に、「PR #41: スカッシュ でマージしました。ブランチを削除しました。#42 の base を main に付け替えました。」と出ます。 設定の 終わったものを非表示にする がオフなら、マージ済み (24 時間) の一覧にも #41 が時刻と方式つきで加わります。 オンのときも、予約時に確認したものと異なる head がマージされた PR は、警告つきで一覧に出ます(マージの結果)。 警告のない結果の行は、設定の マージの結果を隠すまで (分) の時間がたつと隠れます。初期値は 5 分です。 警告がある行は 閉じる まで残ります(マージの結果を隠すまで)。
  2. 積み直しの依頼を確かめるスカッシュでマージしたので、#42 の差分に #41 のコミットが残っています。 #42 には 積み直しが必要 の札が付き、マージできない理由は「積み直し待ち」になります。 常駐サーバーは、PR を登録したセッションに、積み直しの依頼を送ります。 マージコミット でマージしたときは、積み直しの依頼はありません(積み直し、セッションへの知らせ)。
  3. 次の PR をマージするセッションが #42 を積み直して push すると、積み直しが必要 の札が消えます。 条件がそろえば マージできます が出るので、#42 を同じ手順でマージします。 #43 も、#42 のマージのあとに、同じ流れで進めます。
