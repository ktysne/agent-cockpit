使い始める

Agent Cockpit は、導入が済んでいれば、Claude Code または Codex のセッションを開くと自動で動き始めます。 このページでは、ダッシュボードの開き方、起動と終了、連携ツールの有無で変わる表示を説明します。 導入の手順は、導入手順書にあります。

ダッシュボードを開く

ダッシュボードは、次のどちらかで開きます。

  • タスクトレイから開く。Windows では、デスクトップかスタートメニューの「Agent Cockpit」のショートカットで、専用のウィンドウが開きます(タスクトレイ)
  • ブラウザーで http://127.0.0.1:47821/ を開く。ポートを変えているときは、変えた値を使います(ポートと保存先を変える)

セッションを開始したときにも、Claude Code または Codex に、ダッシュボードの URL が Agent Cockpit: http://127.0.0.1:47821/ の形で伝わります。

ダッシュボードは、あなたの PC の中だけで開けます。 別の PC のブラウザーからは、開けません。

最初に開いたとき

導入した直後や、セッションを開いていないときは、一覧にセッションがありません。 Claude Code または Codex で、フックを導入したセッションを開始すると、一覧に出ます。

同じ場所に、終わったものを隠しています。下の「表示する」から表示できます。 や、更新の無いセッションを隠しています。下の「表示する」から表示できます。 と出ることもあります。 このときは、セッションはあるのに、隠しています(終わったものを非表示にする、更新の無いセッションを隠す)。

導入の後に開いたセッションから、一覧に出ます。 Claude Code で導入の前から開いていたセッションは、フックの登録を読み込んでいないので、状態が分かりません(状態不明のセッション)。新しく開き直してください。 Claude Code の記録ファイルの更新時刻が読める状態不明のセッションは、その時刻から設定の時間を過ぎると、更新の無いセッションとして隠れます。初期値は 10 分です(更新の無いセッションを隠す)。 Codex は、フックを信頼するまで一覧に出ません。導入前から開いていたセッションも、次の出来事が届くまで行が出ません。/hooks で信頼し、新しく開き直してください。 それでも出ないときは、セッションが一覧に出ないを見てください。

起動と終了

常駐サーバーは、セッションを開始するとき、フックが自動で起動します。 手で起動する必要はありません。

手で起動するときは、リポジトリのルートで次を実行します。

npm start

手で起動した常駐サーバーは、起動した端末で Ctrl+C を押すと終了します。 フックが起動した常駐サーバーは、セッションもダッシュボードも閉じたまま 30 分たつと、自動で終了します。 次にセッションを開くと、起動し直します(起動と寿命)。

ダッシュボードのウィンドウやブラウザーのタブを閉じても、常駐サーバーは止まりません。 再起動するときは、タスクトレイのメニューを使います(常駐サーバーを再起動する)。

連携ツールの有無で変わる表示

Agent Cockpit は、単独で使えます。 次の 4 つのツールを入れていると、表示と操作が増えます。 入れていなくても、エラーや警告は出ません。 入れたり外したりした後は、画面を開き直さなくても、遅くとも 1 分ほどで表示が変わります。

  • GitHub CLI(gh)：セッションが作った PR を、スタックの形で、CI やレビューの状態と一緒に表示します。スタックの一番下の PR を、画面でマージできます。gh が使えないと、PR の状態を取得できず、登録した PR の欄に赤いエラーが出ます(GitHub CLI が使えないとき)
  • claude-codex-bridge：Claude のセッションのサブエージェントを、Codex と Claude のどちらで動かすかを選べます。サブエージェント の経路の段と、サブエージェントの行の経路の札、Codex のモデルの表示が出ます(経路の設定、経路の札)
  • ai-cross-review：PR のカードにクロスレビューの往復と結論が出て、レビュー収束後マージの予約と、レビュー不要の記録ができます。クロスレビュー の経路の段も出ます(クロスレビューの行、経路の設定)
  • Codex：Codex(CLI とデスクトップ)のセッションも、Claude のセッションと同じように一覧に出ます。判断事項への回答と離席中の推奨の適用に対応します。シェルで作った PR は自動登録されますが、GitHub MCP で作った PR は明示して登録します(PR の登録)。Claude 起点の情報は橙、Codex 起点の情報は青紫の色帯で見分けます(プロダクトのカード)

連携ツールそのものの導入は、それぞれのツールのドキュメントに従ってください。 Agent Cockpit 側に必要な設定は、導入手順書に、ツールごとにまとめています。

連携ツールを見分ける方法の詳細
  • GitHub CLI：PR の取得のたびに gh を実行して、使えたかどうかが分かります。常駐サーバーを起動したプロセスの PATH から探します
  • claude-codex-bridge：Claude のホーム(CLAUDE_CONFIG_DIR、無ければ ~/.claude)か ~/.claude の tools/ に、codex-agent.sh があるかで判断します
  • Codex：Codex のフックが届いたセッションを Codex のセッションとして扱います。導入を調べる処理はありません
  • ai-cross-review：画面が知っているセッションの作業ディレクトリのどれかで、作業ツリーのルートに tools/cross-review.js があるかで判断します。リポジトリごとに入れるツールなので、入れていないリポジトリの PR は、クロスレビューを使っていないとみなして、レビュー不要と表示します

セッションとのつながり

Agent Cockpit は、Claude Code のフックと、MCP サーバーと、スキルでセッションとつながります。 導入の手順書の手順で登録します。

  • フック：セッションの出来事(ツールの実行、サブエージェントの開始と終了、許可待ちなど)を常駐サーバーへ送ります。回答や離席中の指示を、セッションへ届けるのもフックです
  • MCP サーバー(agent-cockpit)：メインセッションが、タスクと完了条件、判断事項、PR を、ダッシュボードに登録するためのツールを持ちます
  • スキル(agent-cockpit)：メインセッションに、これらのツールをいつ、どう使うかを教えます。スキルの本文に書いてあります

Codex は、ホーム(CODEX_HOME、無ければ ~/.codex)の hooks.json に、引数 codex 付きでフックを登録します。 MCP サーバーは config.toml の mcp_servers.agent-cockpit に登録し、各ツールに approval_mode = "approve" を設定します。 スキルは不要で、進め方はセッション開始時のフックが伝えます。 /hooks でフックを信頼する必要があり、フックを変更したときは信頼し直します(Codex の導入手順)。

新しく登録したものは、新しく開いたセッションから効きます。 開いたままのセッションには、反映されません。

フックが伝えること、送る情報の詳細
  • セッションの開始時と、プロンプトを送るたびに、フックは、作業を始めるときにタスクと完了条件を cockpit_set_tasks で登録するよう、メインセッションへ伝えます
  • タスクが登録されないまま作業が進むと、ツールの実行がひと区切りしたところで、登録を促します(メインのツールの実行が 5 回に達したとき、またはタスクの無いままサブエージェントを起動したとき)。サブエージェントが終わった後、10 分以上タスクが書き直されていないときも促します。促すのは、10 分に 1 回までです
  • 離席中は、開発者に尋ねずに推奨を適用して作業を続けるよう、フックがセッションに伝えます(離席中の切り替え)
  • ツールの入力は、要約だけを送ります。コマンドとファイルのパスで、80 文字を超えるときは切ります(メインの作業行)
