困ったとき

このページは、起きたことから、原因と直し方の書かれた節を探すための案内です。 画面に出る文や、見たままの症状から、該当する節を選んでください。 詳しい仕様は、各節のリンク先にあります。

  • タスクが出ない

  • マージできない

画面がつながらない

次の表示が出たときの対処です。

  • 画面の上に 常駐サーバーに接続できません。 と出て、「表示は 14:30 時点のものです」と続く
  • 画面の中央に 状態を取得できません。常駐サーバーが起動しているか確認してください。 と出る
  • ブラウザーが接続できない、または Invalid Host と出る

表示時点の日付が今日と異なる場合は、月日も付きます(例：表示は 10/4 14:30 時点のものです。)。

まず、常駐サーバーが動いているかを確かめます。 ブラウザーで http://127.0.0.1:47821/health を開き、"app":"agent-cockpit" を含む文字が出れば、動いています。 ポートを変えているときは、変えた値で開きます。

  • 動いていないとき：セッションを新しく開くか、タスクトレイの「ダッシュボードを開く」を選ぶと、起動します。リポジトリのルートで npm start を実行しても起動できます。画面は 2 秒ごとに取り直すので、起動すれば自動でつながります。セッションもダッシュボードも閉じたまま 30 分たつと、自動で止まります(起動と寿命)
  • 起動しないとき：保存先の server.log を見ます。診断ログと、サーバーに届かなかったフックの一時記録(diagnostics/hooks-pending.jsonl)も調査に使えます。ポートがほかのプログラムに使われているときは、その旨が書かれます。使っているプログラムを止めるか、AGENT_COCKPIT_PORT でポートを変えます(ポートと保存先を変える)
  • Invalid Host と出るとき：127.0.0.1 か localhost 以外の名前で開いています。常駐サーバーは、この 2 つの名前のどちらかでの接続だけを受け付けます
  • 再起動の直後：起動し直す間だけ、上の表示が出ます。待てば消えます(常駐サーバーを再起動する)

セッションが一覧に出ない

画面に 表示するセッションがありません。Claude Code でセッションを開始すると、ここに表示されます。 と出ているか、開いているはずのセッションが見当たらないときの対処です。

  • 隠していないかを確かめます。一覧の最下部の注記に、隠している種類、外したセッション、終わったもの、更新の無いセッションの件数が出ます(一覧の最下部)。隠している間は、一覧が空になることもあります
  • 導入の後に開いたセッションかを確かめます。フックは、新しく開いたセッションから効きます。導入の前から開いていたセッションは、新しく開き直します
  • フックを正しく登録できているかを確かめます。~/.claude/settings.json の JSON が壊れていないか、フックのパスが本体のチェックアウトを指しているかを見ます(導入手順書)
  • Codex では、ホーム(CODEX_HOME、無ければ ~/.codex)の hooks.json のパスと引数 codex を確かめ、/hooks でフックを信頼します。行の左端に青紫の帯が出れば、Codex としてつながっています
  • 常駐サーバーが動いているかを確かめます(画面がつながらない)

Claude Code の記録ファイルの更新時刻を読み取れる状態不明のセッションは、その時刻から設定の時間を過ぎると、更新の無いセッションとして隠れます。初期値は 10 分です(更新の無いセッションを隠す)。

セッションの状態は、フックが送る出来事から組み立てます。 ~/.claude/sessions/*.json と、Codex のホームの thread-writer-locks/*.lock、session_index.jsonl は、公開仕様ではありません。 読めなくても、フックから組み立てた表示は動きます。

閉じた Codex の行がすぐ消えないことがあります。 TUI は終了操作から約 1 分後に会話の終了が伝わります。 デスクトップのアーカイブは、確認済みのロックファイルが消えてから 60 秒後に終了扱いになります。 codex exec はプロセスの終了を確かめ、その後 60 秒で終了扱いになります(セッションが終わる条件)。

タスクが出ない

タスクは、メインセッションが cockpit_set_tasks で登録したときだけ出ます。 画面の タスクはありません。 が続くときは、次を確かめます。

  • MCP サーバーを登録できているか。claude mcp list で、agent-cockpit が Connected と出れば登録できています
  • Codex では config.toml の mcp_servers.agent-cockpit と各ツールの approval_mode = "approve" を確かめます。スキルは不要です(セッションとのつながり)
  • Claude Code ではスキル(~/.claude/skills/agent-cockpit/SKILL.md)を置けているか
  • Claude Code の MCP サーバーとスキル、Codex の MCP サーバーは、新しく開いたセッションから効きます。開いたままのセッションは、開き直します
  • 別のセッションの欄に出ていないか。MCP サーバーの登録が正しくないと、別のセッションの欄に出たり、どこにも出なかったりします

セッションがタスクを登録しないまま作業を進めると、フックが、ツールの実行の合間に登録を促します(セッションとのつながり)。 更新が無いまま時間がたったセッションは、一覧から隠れます(更新の無いセッションを隠す)。

経路の設定が出ない、効かない

  • 欄が出ないとき：サブエージェントの段は claude-codex-bridge、クロスレビューの段は ai-cross-review を入れていないと出ません。どちらも無いと、欄ごと出ません。クロスレビューの段は、画面が知っているセッションの作業ディレクトリに tools/cross-review.js があるときだけ出ます(欄が出る条件)
  • 変えたのに稼働中のサブエージェントが変わらないとき：経路は、次に起動するサブエージェントから効きます。稼働中のものには、(変更前) の札が付きます(経路の札と「変更前」)
  • 経路の札は付くが、サブエージェントが従わないとき：経路を伝えるフック(route.js)を、登録していません。導入手順書のパターン C を確かめます
  • 保存に失敗したとき：経路の設定を保存できませんでした。 と出ます。常駐サーバーに接続できているかを確かめます

PR が出ない、エラーが出る

  • PR が出ないとき：PR は、セッションに結び付けて登録したものだけが出ます。セッションが gh pr create で作った PR は、自動で登録されます。ほかの方法で作った PR は、メインセッションが cockpit_add_pr で登録します(PR の登録)
  • マージ済みの PR が見えないとき：終わったものを非表示にする がオンだと、マージ済みの一覧は隠れます(終わったものを非表示にする)
  • 赤い枠でエラーが出るとき：gh が見つからないか、認証が切れているか、通信できません。gh auth login でログインし、常駐サーバーの PATH に gh があることを確かめます。GitHub への取得は 60 秒ごとなので、直した後は、遅くとも 1 分ほどで消えます(GitHub CLI が使えないとき)
  • 状態が古いとき：リポジトリの見出しの GitHub から の時間を見ます。この時間は、最後に取得できてからの時間です

マージできない

  • マージする のボタンが無いとき：マージできるのは、スタックの一番下の PR だけです。マージできない理由 の行に、その理由が出ます(マージできない理由と待ち)
  • マージできます と出ないとき：待ち: の行に、満たしていない条件が出ます。条件は、設定の 「マージできます」と出す条件 で選べます(「マージできます」と出す条件)
  • マージする を押した後に失敗したとき：PR の行の下に、理由が 1 分間出ます(マージの前に確かめること)
  • コンフリクト解決 の依頼に失敗したとき：PR の行の下に、理由が 1 分間出ます(衝突の解消の依頼)

回答がセッションに届かない

回答を送ると、回答欄の下に 送信済み、に渡した、に反映された の順に、時刻が増えていきます。 どこで止まっているかで、原因が分かります(送信済み、渡した、反映された)。

  • 回答欄が無いとき：デスクトップアプリのダイアログで答える判断事項です(デスクトップアプリで答える判断事項)
  • 送信済み で止まっているとき：セッションに渡す機会を待っています。セッションが作業中ならツールの実行のひと区切りで、Claude Code が待機中なら回答を待つフックが、渡します。Codex のターン終了後の待ちは、次の項目を見ます。セッションが閉じていると、届きません(回答が届く経路)
  • Codex でターンが終わった後：在席中は、後から届いた回答でセッションを起こせません。離席中にターンが終わったときは最大 59 分待ちます。その間 Codex は作業中の表示で、Esc で中断できます。待ちを終えていたら、次の入力を送ります(回答が届く経路)
  • 常駐サーバーを再起動した後：送信済みの回答は残りますが、次のプロンプトを送るか、ツールの実行がひと区切りするまで、渡りません(再起動で残るものと消えるもの)
  • 離席中の質問に答えたのに、デスクトップアプリに質問が出たとき：質問を預かるフックと連絡が取れなかったときの動きです(常駐サーバーと連絡が取れないとき)
  • 回答を送信できませんでした と出たとき：常駐サーバーに接続できているかを確かめます(画面がつながらない)

設定が保存されない、戻ってしまう

  • 表示の設定を保存できませんでした と出たとき：常駐サーバーに保存できていません。常駐サーバーに接続できているかを確かめます。項目は、最後に保存できた値に戻ります(設定画面)
  • 時間の入力欄の値が元に戻るとき：範囲外の値か、整数でない値を入れています。「1〜120 分の値を入力してください。」のように、範囲が出ます
  • 配色 と 前回見てから が、別のウィンドウで違うとき：この 2 つは、ブラウザーごとの設定です。タスクトレイから開くウィンドウは、普段のブラウザーとは別のプロファイルを使います(設定の保存先)
  • ページを開き直すと戻るとき：ブラウザーに保存できない環境(プライベートウィンドウなど)です。配色 と 前回見てから は、開き直すと最初の設定に戻ります

「画面が新しくなりました」と出た

画面の上に 画面が新しくなりました。書きかけの回答を送るか消すと、読み込み直します。 と出たときです。 リポジトリを更新して、画面のファイルが変わったときに出ます。 書きかけの回答があるときは、読み込み直すと消えるので、すぐには読み込み直さずに、この表示を出します。 回答を送るか消すと、自動で読み込み直します。今すぐ読み込み直す を押すと、書きかけの回答を捨てて、すぐに読み込み直します。

タスクトレイが動かない、通知が出ない

  • 起動しても何も出ないとき：PowerShell の実行ポリシーが Restricted のままだと、何も表示せずに失敗します。RemoteSigned 以上にします(タスクトレイを起動する)
  • アイコンが灰色のとき：常駐サーバーに接続できていません。セッションを開くか、ダッシュボードを開くと、起動します(起動と寿命)
  • 通知が出ないとき：メニューの「待ち件数を通知する」にチェックが入っているかを確かめます。最初の設定は、通知しないです。タスクトレイを起動した時点で、すでにあった許可待ちと判断待ちは、通知しません(待ち件数の通知)
  • ダッシュボードが開かないとき：Edge か Node.js が見つかりません、という通知が出ます。普段のブラウザーで http://127.0.0.1:47821/ を開けば、同じ画面が使えます

不具合を調べるための記録

不具合を調べるときは、設定画面の 診断ログ を開き、すべての起動を書き出す で保存したファイルを調査担当者に送ってください。 操作と保存する情報は、診断ログで説明しています。
